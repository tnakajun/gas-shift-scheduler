# シフト生成・労務制約仕様書 (rules.md)

本ドキュメントでは、`gas-shift-scheduler` が準拠するシフト生成ロジックおよび労務コンプライアンス（バリデーション）の仕様について定義します。

---

## 1. 運用モード定義

Config シートの「運用モード」パラメータに応じて、3つの生成アルゴリズムを切り替えます。

| モード名 (`mode`) | 対象業務イメージ | シフト割り振りルール |
| :--- | :--- | :--- |
| **`WEEKDAY_ONLY`** | 平日型オフィス・保守業務 | ・月〜金：日勤<br>・土日祝：公休 |
| **`DAY_365`** | 365日対応サポート（日中） | ・年中無休の日中シフト体制<br>・週休2日をベースとした循環ローテーション |
| **`FULL_24_365`** | 24時間365日インフラ監視・交代制 | ・4勤4休サイクル（日勤 ➔ 夜勤 ➔ 明 ➔ 休）<br>・前月末の勤務実績を引き継いで月初を生成 |

---

## 2. 労務制約・バリデーションルール

`validator.js` が自動検証する労務コンプライアンス基準です。違反を検知したセルは背景色が変化し、セルノートに警告理由が出力されます。

### ① 最大連続勤務日数の制限（労働基準法・過重労働防止）
* **ルール**: 日勤・夜勤の連続勤務が設定値（デフォルト **5日**）を超過した場合に検知。
* **判定**: 6連勤目以降のセルを赤色ハイライト（`#FCE8E6`）およびエラーカウント。
* **リセット条件**: 「公休（休）」または「明け（明）」を挟むことで連続カウントをリセット。

### ② 夜勤翌日の連続勤務禁止（インターバル規制）
* **ルール**: 「夜勤」の翌日に「日勤」または「夜勤」が割り当てられることを禁止。
* **判定**: 翌日セルが「明」以外の場合に赤色ハイライト（`#FCE8E6`）およびエラーカウント。

### ③ 明け翌日の公休確保推奨（健康管理基準）
* **ルール**: 24/365交代制において、「明」の翌日は原則「公休（休）」を推奨。
* **判定**: 「明」の翌日に勤務が入っている場合、注意アラートとしてオレンジ色ハイライト（`#FFF0D4`）およびエラーカウント。

---

## 3. 前月引き継ぎロジック (prevMonthReader)

月またぎのシフト破綻を防ぐため、前月シート（例: `2026_08`）の末日データを自動走査します。

* **前月末日が「夜勤」の場合** ➔ 当月1日は自動的に **「明」** からスタート。
* **前月末日が「明」の場合** ➔ 当月1日は自動的に **「休」** からスタート。
* **月末時点での連勤数** を当月1日以降の連勤判定に加算（月をまたいだ過重労働を防止）。
